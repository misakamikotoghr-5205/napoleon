# 示意图 C：2.5D 景深（HD-2D 风格）河街: 制作笔记

成品：`C_25d_street.png`（1280×720，Godot 4.7 实机渲染，未经后期 PS）
工程：`c_fast/`
- `gen_c.py`：用 PIL 生成贴图和 `layout.json`，复用 `assets/` 与 `gen_buildings.py` 等生成器，只读不写。
- `proj/main.gd`：运行时程序化搭建整个场景，约 860 行 GDScript。
- `render.sh`：一键渲染。
- `render_r5_pitch26.png`：中间一轮的版本（俯角 26°），留作对比。

## 1. 渲染器

- **Forward+ 能用。** 容器内原本没有任何 Vulkan ICD。我用 `apt-get download` 下载了 `mesa-vulkan-drivers` 的 .deb，只解包到 scratchpad，没有安装进系统。再用 `VK_ICD_FILENAMES` 指向其中的 lavapipe（llvmpipe，纯 CPU 软件光栅），就跑起了 `--rendering-driver vulkan` 加 Forward+。
- **渲染速度。** 用 CPU 渲染一帧约 20 秒（含启动）。如果换成真显卡，同样的场景是实时帧率。
- **Compatibility 渲染器这次没有用到。** 景深、Glow、SSAO 都是引擎原生效果，不需要用模糊 shader 去模拟移轴。

## 2. 哪些是"真"的，哪些是"假"的

| 效果 | 做法 |
|---|---|
| 移轴景深（上、下虚化） | **真**：`CameraAttributesPractical` 同时开远景虚化和近景虚化，bokeh 质量设为高。后排屋顶、近处水面和鸭子都会自然虚掉 |
| 太阳光与阴影 | **真**：`DirectionalLight3D`（暖色、低角度，从左前方照来），4 段 PSSM 软阴影。当字马头墙投在米行屋顶上的影子、桥栏杆的影子都是实时算出来的 |
| 灯笼与路灯暖光 | **真**：每盏灯一个 `OmniLight3D`，墙面上能看到暖色光斑。光晕是引擎 Glow 加上一张叠加（additive）的柔光贴片 |
| SSAO、景深雾、Filmic 色调映射、对比度与饱和度 | **真**：在 `Environment` 里设置 |
| 建筑 | **半真**：建筑本体是 3D 盒子，正面贴的是 A1 现成的立面像素图。我在生成时把 `roof_layer` 替换成空图，屋顶就被抹掉了。侧墙用平铺的白灰贴图 |
| 屋顶 | **真几何**：用 SurfaceTool 程序生成，坡面微凹，两端起翘，檐口有一条勾头瓦当，屋脊两端有翘角。二层腰檐也是真几何，下方会投下真实阴影 |
| 马头墙 | **真几何**：5 段阶梯盒子，各自取同一张"当"字贴图里的一块 UV，墙头有瓦帽和座头 |
| 石拱桥 | **真几何**：用 `CSGPolygon3D` 挤出驼峰桥身和券洞，另加券石圈、栏板和望柱，贴三平面投影的石材贴图 |
| 水面倒影 | **假**：没有用 SSR，也没有用平面反射。桥和驳岸是复制一份再沿 Y 轴镜像放到水下，上面盖一层半透明、不受光照的水面贴图；船的倒影是一张上下翻转的 Sprite。效果是"颜色更暗的倒影"，桥洞下面能看出一点"满月"的感觉 |
| 水面碎金 | **假**：几十个横向的叠加小面片，再借 Glow 发亮 |
| 体积光（光柱） | **假**：屏幕空间里一个叠加 shader 画的斜向光带，跟场景几何没有关系 |
| 暗角 | **假**：CanvasLayer 上的 shader |
| 空中浮尘 | **假**：叠加的小 billboard 面片 |
| 人物、柳树、道具 | 都是 `Sprite3D`，开启 billboard、最近邻过滤、alpha 裁剪，不参与光照，只调一个暖色 modulate |
| 人物脚下阴影 | **假**：用 blob 阴影面片。原因是 Sprite3D 投出的实时阴影会随光源方向扭曲，很难看 |
| UI（日期/时间/钱、对白气泡、"尚未开放"锁牌、角标） | 先用 PIL 按像素字体预渲染成 PNG，再用 TextureRect 显示在 Godot 里。气泡和锁牌的位置由 `Camera3D.unproject_position` 根据 3D 坐标实时算出 |

## 3. 迭代过程（共 6 轮）

1. **第 1 轮**
   - 场景已经成形。
   - 问题：屋檐出挑太深，把"茶馆""德厚当"招牌全挡住了；对白气泡又盖住了"当"字；水面饱和度过高。
2. **第 2 轮**
   - 墙顶加一条白灰檐下带，同时减小进深和出檐，招牌露了出来。
   - 对白改成两行，尾巴放在右下角。
   - 水面改成半透明加镜像倒影。
   - 加入光柱和浮尘。
3. **第 3 轮**
   - 加"河床/天光"底色。之前透过透明水面看到的是米色背景，水像沙地。
   - 柳树挪到马头墙前面，正好挡住空白的墙脚。
   - 加"尚未开放"锁牌。
4. **第 4 轮**
   - 人物往前站约 4 m。人站得越近，在屏幕上越靠下，气泡就不会再压到二楼的招牌。
   - 加水面碎金，镜头右移。
5. **第 5 轮**
   - 修正碎金的绘制顺序。
   - 墙脚和岸边加小草。
   - 近景虚化稍微加强。
6. **第 6 轮**
   - 俯角从 26° 调到 30°，符合要求的 30–40° 范围。
   - 屋面加细分，消掉坡面中间那道折痕高光。
   - 柳树色调压暗。

**仍然存在的瑕疵（如实列出）：**
- 后排屋顶被远景虚化糊成一片灰褐色，层次不够。
- 柳树不受光照，颜色偏平、偏亮。
- 桥面没有做台阶。
- 立面贴图里本来画好了"檐下阴影"，现在又叠了一层真实阴影，个别地方显得重复。
- 画面是一张静帧，没有做动画。

## 4. 和 2D 俯视小镇（A/B 方案）相比，难度大多少（实话）

**一句话：** 这张图看着"像 Octopath"，但做成能玩的游戏，美术和程序的工作量都要比 2D 俯视方案明显多出一截。按我的粗略估计，每个场景的美术量约是 2–3 倍，程序的基础设施和日常调试约是 1.5–2 倍。另外还有一笔持续存在的"调光调景深"的时间。

### 美术侧

- **贴图要拆层。** 2D 方案里，一张建筑图把墙、屋顶、阴影一起画完就行。2.5D 必须拆成正立面（可以平铺）、侧墙、屋面、檐口、屋脊、山墙几部分，各部分接缝和像素密度（这里统一为 16 px/m）都要对齐。这次能做得快，是因为现成的生成器可以去掉屋顶重新导出；如果是手绘，每栋楼都要按这个规格重画一遍。
- **光影不能再画死。** 2D 里阴影、高光都画在图上。3D 里光是实时算的，所以贴图要画得"中性"，否则烘焙进去的阴影会和真实阴影打架（本图的腰檐下就有这个问题）。这样一来，美术在画面上的直接控制力反而变弱。
- **立体的东西得会建模。** 屋顶、桥、马头墙这些都要几何。中式屋顶的起翘、凹曲，正是最难做好的部分。本图是程序拼出来的，近看还是能看出"盒子感"。
- **角色反而变化不大。** 角色依然是 2D 图，4 方向 × 3 帧可以直接复用。但它们不吃光照，要显得"融入"场景，就得逐个场景调色。如果改成吃光照，又需要另画法线图。
- **场景氛围靠调参数。** 景深、雾、Glow、色调映射、灯光，每个场景都要调。这种调整没有"画完就定"的时候。

### 程序侧

- **场景搭建方式变了。** 2D 只要 TileMap 加 Y 排序。2.5D 需要 3D 关卡编辑流程：GridMap 或模块化建筑套件、碰撞体、3D 导航。玩家移动、交互判定、遮挡（人走到屋檐下、树后面）都要处理。
- **Billboard 精灵的老问题。** 包括：
  - 半透明物体的排序；
  - 精灵和墙穿插，本图把精灵整体后仰以保持像素是正方形，靠墙太近就会穿进墙里；
  - 像素在透视下大小不一（近大远小，出现所谓"mixel"）；
  - 镜头一动，最近邻过滤的贴图会闪烁、出现摩尔纹，加 mipmap 或 TAA 又会把像素糊掉。
- **性能和平台。** Forward+ 加景深、SSAO、阴影，对核显和 Steam Deck 一类设备并不轻。Compatibility 渲染器没有原生景深，只能自己写模糊 shader 来模拟（本次没走到这一步）。如果要上网页版或手机，这一点更关键。
- **倒影和水。** 想要好看的水面倒影，要么用 SSR（只能反射屏幕里看得到的东西），要么做平面反射（多渲染一遍），要么像本图这样复制镜像几何。三种都比 2D 里直接画一张"倒影图"麻烦。
- **UI 与 3D 的衔接。** 气泡、锁牌、交互提示都要从 3D 坐标投影到屏幕。镜头一动，就要处理它们的跟随、遮挡和越出屏幕边缘的情况。
- **本次代码量参考。** 静态单镜头一张图，约 860 行 GDScript 加约 450 行 Python 贴图脚本，渲染 6 轮。A1 的 2D 合成脚本约 470 行。

### 建议

- 如果团队很小，或者美术主要靠程序生成：继续走 2D 俯视（A/B），成本可控、风格稳定。2.5D 的"景深、实时光、柔光"可以拿来做局部点缀，比如过场镜头、标题画面、少数几个固定机位的重点场景。
- 如果确定要做 2.5D：
  - 只用**固定机位、固定俯角**，不做自由旋转；
  - 只做**一套模块化的江南建筑件**（墙段、屋面、马头墙、桥），在各场景之间反复复用；
  - 尽早定下**像素密度和光照规范**，否则后期返工量很大。
