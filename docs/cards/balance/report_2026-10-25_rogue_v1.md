## 验收口径

关 1/2/3 = 1938 三月 / 1939 腊月 / 1940 三月（JSON 的 stage 0/1/2）。过关数的分母是 20，没走到的算没过。“月底现金中位数” = `aggregate.py` 的 `month_money.median`：只算走完那个月（`year_jump` 或 `ending`）的局，取排序后的第 `(n−1)×50//100` 个。下文括号里是这个 n。

| 条 | 怎么判 |
|---|---|
| A1 | refuser 每一关：过关数差 ≤ 1，且现金中位差 ≤ 关的 5% |
| A2 | trader 每一关 开过关 ≥ 关；第 2、3 关现金中位 开×100 ≥ 关×110 |
| A3 | fair 每一关 开过关 ≥ 关 − 1 |
| A4 | 第 3 关：（trader 开 − refuser 开）>（trader 关 − refuser 关） |
| A5 | 三关（开 − 关）现金中位之和：idle < trader（规格没说哪一关，取三关合计，逐关也列出） |
| A6 | on 份周末盘账摆出 3 样的份数 ÷ 周末盘账份数（三关合计，不含货郎）：trader ≥ 60%，idle ≤ 10% |
| A7 | on 份全部局里 12 件、6 种都摆出过；trader ∪ random 挑过全部 12 件 |

诊断（b0 逐局数据）：

1. A2、A4 都卡在 trader 第 3 关现金。refuser 两边都是 84，所以 A4 等于“开 > 32”，A2 等于“开 ≥ 36”。走完第 3 关的局，开 11 局：`0,0,0,0,0,23,28,34,48,112,554`；关 9 局：`0,0,0,0,32,112,144,195,287`。两边都走完的 9 个种子，配对差均值 −0.6。开的一边多两局走到月底（种子 6、17），两局现金都很低，拉低了中位数。月底为 0 的局，是月账开销（30 × 物价指数）吃光了现金；trader 又不押家当，现金都换成了货。
2. trader 按“镇店 > 有来历 > 寻常”挑，第 3 关博古格上最多的是紫檀算盘（按周计 25）和老匾木心（22）。两件原来的价钱偏向只有 95/105 和 110。

## 风险与没解决的

1. A2 第 3 关很脆。开 12 局：`0,0,0,0,34,45,112,235,461,528,563,816`；关 9 局：`0,0,0,0,32,112,144,195,287`。两边各 4 局月底是 0，幸存者构成也不同。b2→b3 只改一个毛病，中位数就从 34 跳到 45，噪声在 ±10 量级。要下结论得用更多种子。
2. idle 第 3 关 12/20（关 20/20）：8 局入狱的都从第 2 关起摆着老匾，12 局幸存者都是第 3 关才拿到。这是 A5 要的“拒绝不划算”，但代价不小。b2 的权重改动让报价随机数换了，多了 2 局入狱。
3. fair 第 3 关现金 0 对 62（n 8/9），A3 只看过关。两边大多在牢里（被抓 62/58），这是 W2 #198 报告就记下的牢房压力。开了以后风声 ≥ 第 3 档的日数是 132 对 83。
4. trader 第 1 关现金 41 对 49，略低。
5. trader 第 3 关风声 ≥ 第 3 档的日数 130 对 55，被抓 42 对 38，主要来自老匾。
6. 客源在 1938 第 0 周以后几乎不被 fair、trader、idle 挑（`slot_kinds` 第一格是物件，trader 物件优先）。客源效果只有第 0 周和 random（挑过 56 次）的样本。
7. 黄金种子：真数据用例因本次 `relics.json` 再变（`0a2d663e` 上第 10 天 `a7a29f37…`）。例子集不读 `era/common/relics.json`，那条用例不变（`1e22bf9e…`）。本阶段未动 `golden.json`。
