## 接口

| 函数 | 作用 |
|---|---|
| `new_battle(template_id, setup)` | 建一场战斗，返回状态字典。`setup.template` 可以直接给一张模板字典（测试用）。模板坏了返回 `{error, errors}`。 |
| `apply(state, cmd, args)` | 下指令，返回 `{ok, err}`。被拒绝时状态一个字节都不变。 |
| `intents(state)` | 本回合敌情：每个敌人的移动终点、攻击目标、伤害、标记（`hunter` 靶心、`execute` 骷髅、`decap` 斩首令），被我方 a 步先手打死（或敌军已经溃逃）的标 `cancelled`；炮击准星；斩首令（`type: decap`）；之后 2 回合的来敌（带全部标签）。 |
| `preview(state)` | 在深拷贝上结算本回合，返回结算后的兵力、位置、军心、倒下名单，不改 state。 |
| `preview_cmd(state, cmd, args)` | 指令预演：在深拷贝上先下一条指挥阶段的指令（不交火），返回单位落点、打到的格子 `hit_cells`、挨打敌人剩多少、击毙数、双方军心、军令点、新增日志；不改 state。界面选骠骑兵朝向时用它画冲锋。 |
| `result(state)` | 战后：胜负、星级、奖赏、命悬一线铜钱、伤痕、被俘、溃散的部队、用过的羁绊、信赖 +1 名单、征发次数。 |
| `view(state)` | 界面要画的一切：格子与地形、路线、我方单位、部署栏、敌人、敌情、军令点、双方军心、回合、波次条（`detail` 带每个来敌的标签）、手牌（能不能打）、放到一边的牌 `set_aside`、能不能换牌 `can_redraw`、预留炮位 `cells[].reserved`、斩首令回合 `decap_turn`、羁绊栏、中文日志。 |
| `load_templates()` / `validate_template(t)` | 读取并校验模板。 |
| `load_state(data)` | 读档：把 JSON 往返后的存档（数字全变成了浮点）整份转回整数，坏存档返回 `{error: "bad_save"}`。其余入口发现整数字段是浮点时也会自动转，所以存档直接传回来也行。 |

指令：`deploy {unit, col, row, facing}`、`withdraw {unit}`、`skill {unit, col?, row?, mode?}`、`card {index, unit?, col?, row?, enemy?}`、`aim {unit, col, row}`、`formation {unit, square, index?}`、`carry {unit}`、`redraw {index}`、`undo`、`fight`、`retreat`。

参数类型不对（`col` 给了数组、`index` 给了字符串、`square` 给了字符串……）一律返回 `{ok: false, err: "bad_args"}`，不报脚本错误，也不改状态。`unit / facing / mode` 要字符串，`col / row / index / enemy` 要整数（JSON 来的 `1.0` 算整数），`square` 要布尔。

坐标 `col`、`row` 从 0 开始；界面标签 A1 =（0, 0），A 列是我方鹰旗一侧，行 1 在最上。朝向 `left / right / up / down`。

## 确定性

- 状态只放整数、字符串、布尔、数组、字典，没有浮点；所有乘除都是整数运算，向下取整。
- 战斗中没有随机数。随机只有两处，都来自 `state.seed` 的 xorshift32：
  - 进场时：每一波的备选构成（模板里的 `alt`），以及军令牌组的初始洗牌；
  - 战后：命悬一线的铜钱。`result()` 每次都从种子重新推，同一个状态永远是同一组铜钱。
- 每个人的铜钱是一条独立的整数流（种子 + 名字的 FNV-1a 散列）。别人多一枚少一枚、谁先倒下都不影响他；自己多加一枚（以后的金币加铜钱），前面几枚的正反也不变。
- 牌组抽空后，弃牌按开场洗好的顺序收回，不再洗。
- 存档就是 `JSON.stringify(state)`；读回来交给 `load_state()`（或者直接传给任何入口），之后的结算和没存过档一模一样。

## 回合

1. 敌情：开局和每回合开始时锁定。敌炮每 2 回合一炮，开炮前一回合定准星（模板可用 `first_fire` 指定第一炮；阿尔科莱的 G1 炮第 2 回合亮准星、第 3 回合开第一炮，和设计稿实例一致）。远程敌人按预测的落脚点锁定目标，之后目标撤走就打空。打出佯动当场改那一个敌人的目标；打出号手只重算号手那一行的远程目标，而且不碰本回合被佯动挪过的目标。
2. 指挥：不限时，所有操作都能逐级撤销。撤销栈在指挥阶段开头清空，按「交火」后就不能撤了。本回合刚部署的单位不能撤下（后撤牌也不行），放错了用撤销。
3. 交火：
   - a 我方远程：炮兵 → 猎兵 → 横队；同兵种按出征名单顺序。打死的敌人立刻移除，它的意图作废。
   - b 敌人移动：离鹰旗近的先走，同距按编号；判定阻挡；走进鹰旗的扣军心并移除。
   - c 白刃：先算完双方所有伤害，再一起落下。
   - d 敌方远程和炮击。
   - e 结算：部队溃散、伙伴濒死、主角倒下 → 军心 → 军医和随军家眷治疗 → 充能 +1、装填与冷却 −1 → 判定胜负 → 下一回合：地形事件、新的一波、军令点、补牌、斩首令、锁定敌情。
   - 敌军心一归零就当场溃逃：在指挥阶段（骠骑兵冲锋、点名、刺刀冲锋）归零，按交火后敌方什么都不做，直接进 e 步判胜；在 a 步或 c 步归零，后面的敌方步骤跳过。敌情里溃逃敌人的意图全部作废。

## 阻挡（三条定死的规则）

- 敌人每到一格（包括出发那一格），先看前方：沿路线从下一格起、连续站着我方单位的那一串格子（濒死伙伴和拒马也算）。
- 这一串里第一个阻挡数还够的单位挡住它：敌人停在这一串的正前方，算被那个单位挡住，之后不再移动，直到阻挡者撤走、倒下或阻挡数变少。所以前排满员时，紧挨在后面的单位会接着挡（纵深阻挡，双方隔着前排互打），不会被跳过去。
- 这一串全部满员：整串是通路，敌人直接穿过去，这就是漏怪。它不会停在我方单位的格子上：步数刚好走到这一串里时，顺延到这一串后面的第一个空格（相连的满员单位算一道墙，一次顺延过去）。
- 匈牙利掷弹兵占 2 个阻挡位；只剩 1 个位置时它直接漏过去，后面有 2 个空位的单位会接住它。

## 军心与胜负

- 我方开场 10（setup 可给 `morale`），上限 15，意大利军团 4 档 +2。
  - 加：主角登场 +3、击杀精英 +1、击杀纵队长 +2、开箱发饷 +1、皇帝的命令 +3。
  - 扣：敌人进鹰旗 −2（精英 −3）、部队溃散 −1、伙伴倒下 −2、主角倒下 −5、主角中途撤下 −2。
  - 军心 ≤3 时撤退不返还军令点。
- 击杀扣敌军心：步兵和弹药车 −1，骑兵和炮 −2，精英 −3，纵队长 −4。
- 胜：敌军心归零（溃逃，奖赏升一档）；所有波次出完并清空（一个都没漏是「来敌全歼」`cleared`，有漏进鹰旗的只算「敌军攻势耗尽」`spent`）；撑满回合上限、军心仍 >0（坚守）。败：我方军心归零。都在 e 步判定（溃逃可以提前，见上）。
- 星级：★ 获胜；★★ 再加军心不低于开场的一半；★★★ 再加完成皇帝的命令，并且没有伙伴倒下。
- 奖赏：遭遇战 50 法郎 + 1 勋章，精英战 90 + 2，会战 200 + 3 + 1 金币；每多一星（溃逃再多一档）法郎 +25%、勋章 +1；完成皇帝的命令勋章 +1；主角打完仍在场法郎 ×1.5、勋章 +1（会战 +2）；军需官的人在场法郎再 +20%。

## 主角

- 0 费，每场只能部署一次，撤下后不能再上。
- 在场时每回合军令点 +1，点亮军需官的人。
- 站住！：在场时军心第一次掉到 3 以下，拉回 3，主角兵力 −4（最低留 1）。
- 猎官（龙骑兵、带 hunter 标签的炮或远程）：走到主角相邻格就停下打他，不占任何人的阻挡位；带 hunter 的炮把准星放在主角身上。敌情里标 `hunter`，波次条和敌情里的来敌也带上兵种自带的标签（龙骑兵提前两回合就显示猎官）。
- 会战里的猎官数按设计稿逐幕加：第 1–6 幕 0 / 1 / 1 / 2 / 2 / 3（里沃利和 major_a 都照这张表）。通用遭遇战和精英战里，能站人的每一格都挨着一条敌人的路，主角躲不到够不着的后排。
- 斩首令（设计稿“主角·风险”）：第 4 幕起的精英战和会战，敌将每场一次。主角在场的第一个回合（第 3 回合起）发令，敌情里亮出 `decap`；下一回合所有敌方远程只要够得着就打主角，那一回合开炮的敌炮准星也落在他身上（可以用佯动挪开、先手拔掉，或者撤下主角）。遭遇战没有敌将，没有斩首令。
- 不上场时可以用「后方调度」（对主角下 `skill`）：军令点 +3，每场一次，用了就不能再上阵。
- 倒下：离场，军心 −5，战后掷 2 枚铜钱。倒下时有信赖 ≥2 的伙伴在相邻格 +1 枚（护卫），拉雷在场 +1 枚，最多 4 枚；全反面阵亡。主角在场时输掉：直接被俘，不掷。

## 伙伴

- 兵力归零进入濒死：留在原格，阻挡 0，不攻击，不计入羁绊，军心 −2。
- 抬下：2 军令点，相邻要有我方单位；军医相邻免费。濒死期间任何指挥阶段都能抬。
- 战后：
  - 没有伤痕、被抬下（在下一次敌方阶段之前）：只留伤痕；
  - 没有伤痕、没被抬下、撑过了下一次敌方阶段：伤痕 + 命悬一线；
  - 带伤（或在宿命之地，按带伤算）：命悬一线，被抬下 +1 枚；
  - 输掉（军心归零）时没被抬下：被俘，不掷。
- 命悬一线：基础 3 枚；处决 −1、宿命之地 −2、被抬下 +1、拉雷在场 +1、随军家眷 +1、撤出且没被抬下 −1；最少 1 枚、最多 5 枚；全反面阵亡。
- 随军家眷那一枚按她倒下之后的羁绊算：倒下的家眷不再计入随军家眷，所以只剩她一个时拿不到 +1。军需官的人「第一个倒下的伙伴视为已被抬下」看的是倒下那一刻的档位。
- 伤痕和宿命之地：进场时兵力上限 −25%（向下取整）。

## 羁绊

职业羁绊数场上所有单位（拒马除外），阵营羁绊只数伙伴和主角。部署、撤下、倒下、抬下都会立刻重算。同时生效最多 3 条：档位高的优先，同档按下表顺序。

| 羁绊 | 类型 | 效果 |
|---|---|---|
| 炮兵学派 | 炮兵 | 2：不用隔回合装填；3：穿透全额，炮兵攻 +1 |
| 方阵 | 掷弹兵，必须相邻（取最大的相连组） | 2：组内防 +1；3：组内阻挡 +1 |
| 骑兵预备队 | 骠骑兵 | 2：冲锋距离 +1；3：冲锋打死敌人返还 2 军令点 |
| 意大利军团 | 阵营 `italy` | 2：开场军令点 +2；3：每回合军令点 +1；4：军心上限 +2，每击杀一个纵队长全体充能 +1 |
| 军需官的人 | 阵营 `quartermaster`，主角必须在场 | 主角 + 1 人：战后法郎 +20%；主角 + 2 人：本场第一个倒下的伙伴视为已经被抬下 |
| 随军家眷 | 阵营 `family` | 2：伙伴命悬一线 +1 枚；她们 2 格内的单位每回合回 1 |

## 军令牌（8 张）

齐射（2）、刺刀冲锋（1）、佯动（1）、虚张声势的号手（2）、集中炮火（2）、后撤（0）、征发（0）、皇帝的命令（0，会战限定，用后消耗）。每回合补到 3 张。方阵扣住的牌占手牌位、不能打出，解除方阵后回到手上。

- 整场都打不出的牌开场就放到一边（`state.set_aside`，视图里也列出来），不进牌组、不占手牌位：非会战的皇帝的命令；名册里没有炮兵时的集中炮火；没有远程单位时的齐射；没有近战单位（含带来的主角）时的刺刀冲锋。
- 换牌 `redraw {index}`：每回合一次，免费把一张没扣住的手牌放进弃牌堆，从牌组补一张；可以撤销。
- 集中炮火只能指定至少一门炮射程图样里的格子，而且只调动射程够得着那一格的炮（它们无视装填）；够不着的炮照常行动。
- 后撤也不能撤本回合刚部署的单位。

## 模板

- `map` 每行一个字符一格：`.` 平地、`^` 高地、`=` 道路、`v` 村庄、`w` 树林、`~` 河、`b` 桥、`f` 浅滩、`m` 沼泽、`G` 红门、`E` 鹰旗。胸墙是工兵筑出来的高地。
- `routes`：每条路线是一串格子，必须起于红门、止于鹰旗、逐格相邻，中间每格都能走。
- `waves`：`turn` 是这一波第一次出现在格子上的回合（第 1 回合的波次开场就在）。走路线的写 `route`，炮写 `at`。可以有 `alt` 备选构成、`act_min`。炮可以写 `first_fire`（第一炮的回合，至少是出现的下一回合）。
- 炮位（`at`）必须是高地或平地、不在任何路线上；炮出现之前这一格是「预留」的（视图 `cells[].reserved`），不能部署、不能放拒马，免得炮刷在我方单位头上。
- `events`：某回合某格变成新地形，例如阿尔科莱第 5 回合 E3 变浅滩。校验时路线按它第一次被用到的那一回合的地形检查。
- `order`：皇帝的命令，`hold`（某回合结束时我方有单位站在某格）或 `no_leak`（没有敌人走进鹰旗）。

## 模板难度

- 每张模板都满足「什么都不做必输」：不部署任何人（或只用后方调度）连按交火，第 1–6 幕都在回合上限之前被漏怪打到军心 0。测试里逐模板、逐幕跑。
- 通用模板和里沃利上，只放主角（任何一格）然后连按交火也赢不了；阿尔科莱第 1–2 幕可以把主角放在西堤道上当诱饵拖住两名龙骑兵，换一个 ★ 的险胜，但主角必然倒下、要掷铜钱。
- 敌兵力、攻、军心按幕放大之外，模板用 `act_min` 按幕加兵：遭遇战第 3 幕起多一个白衣、第 5 幕起多一名龙骑兵；精英战第 2 幕起有处决炮和第二名龙骑兵、第 4 幕起多一名格伦茨；会战按猎官表加猎官。
- 拿一个贪心滚动机器人（每步模拟之后 4 回合挑最好的一步，名册 4 伙伴 + 6 部队，全是第一幕数值）实测 5 张模板 × 第 1/4/6 幕 × 带不带主角 × 2 个种子：60 场全胜，平均星数第 1 幕约 ★★★，第 4、6 幕约 ★★（会战 major_a 第 6 幕不带主角只剩 ★），漏怪和伙伴倒下随幕增加。机器人能看全预演、名册也全，比普通玩家强，所以这只能说明难度在随幕上升，不是最终胜率。
- 同一组实测里主角一次也没倒：机器人每一步都看预演，总能护住他；第 4 幕起带主角的星数普遍更高。对会算的玩家来说，亲临前线仍然划算，猎官和斩首令让它要花兵力和军令点去保。设计稿要的 40%–60% 选择率要等战役层（重伤缺阵、被俘轮盘、奖赏）接上以后再用人或更像人的机器人测。

## 和设计稿不一样、或者设计稿没写死的地方

1. 击杀扣敌军心按设计稿「战斗（总述）」的表（步兵 −1、骑兵/炮 −2、精英 −3、纵队长 −4），没有用任务说明里的简写（−1 / −2 / −3）。设计稿的阿尔科莱实例里，打掉奥军炮正好是 −2。
2. 意大利军团 2 档的「开场军令点 +2」按出征名单算（开场时还没人上场），名单里的伙伴加上带来的主角，有 2 个 `italy` 就加。3、4 档按场上实时算。
3. 远程敌人在回合开始时锁定目标；之后新部署的单位它不会临时改打，除非被那个单位挡住（被挡住就打挡住它的人）。
4. 敌炮瞄准：猎官炮瞄主角；否则瞄离它最近的我方地面单位（高地上的单位排在后面），同距打兵力低的。设计稿只给了实例。
5. 猎官的「移动加攻击范围」做成：沿路线走，到了主角相邻格就停下打他。
6. 骑兵冲锋：前方 3 格内没有敌人就原地不动、不冲；冲锋穿过的格子必须是骠骑兵能站的空地。
7. 「濒死伙伴撑过下一次敌方阶段」：濒死后每经过一次交火记一次。没被抬下、胜利时还没撑过任何一次敌方阶段的，按战后收容处理，只留伤痕。濒死伙伴不再挨打。
8. 输仗没人收容 −1 枚：只有「撤出」会用到。军心归零的败仗里，没被抬下的伙伴照设计稿第 5 条直接被俘。
9. 站住！会让主角兵力 −4，但最低留 1，不会因此当场倒下。
10. 动摇（军心 ≤3）只影响普通撤下；「后撤」牌照牌面全额返还。
11. 「后方调度」和亲临前线二选一：用了就不能再上阵。
12. 树林按「挨远程时防 +2」算，伤害仍然至少 1。
13. 敌我同时在 e 步归零时判败。
14. 没做的：泥地、敌将令和其余敌将规则、名羁绊（老相识、替你挡枪、老对头）、疲惫、金币加铜钱、拉雷的担架和其他道具、交给副官、援军/被俘轮盘（交给战役层）、参谋型伙伴补到 4 张、诅咒牌。
15. 顺延：设计稿写「顺延一格」，是按一个单位写的。两个满员单位挨着站时，只顺延一格会落在第二个单位的格子上；如果因此让敌人停下排队，两排满员的单位就成了谁都过不去、也不挨打的墙，漏怪就没了。这里把相连的一串满员单位当一道墙：整串都满才穿过去，顺延到墙后第一个空格；串里只要有一个还有空位，就由它挡住（纵深阻挡）。
16. 斩首令发令时机：设计稿只说「敌将每场一次，提前一回合预告」。这里取主角在场的第一个回合（第 3 回合起）发令，下一回合执行；只影响远程和那一回合开炮的炮，白刃敌人不变。
17. 阿尔科莱第 5 回合 H3 开门时来两名龙骑兵（设计稿实例的波次条写的是一名）。只有一名时，就算什么都不做，到第 8 回合也只漏 4 个敌人（军心 10 → 2），坚守胜利。第 3 回合实例的局面（F2 两个白衣、G2 格伦茨、G1 炮第 3 回合开炮、准星在 D2）不变。
18. 设计稿说遭遇战敌方总兵力约为会战的 15%、精英战约 35%。按这个比例，遭遇战的敌人连走进鹰旗都扣不到 10 点军心，什么都不做也能坚守获胜，所以通用遭遇战和精英战的兵力明显高于这个比例（遭遇战开场 4 人 + 2 名龙骑兵，精英战两路同时压上）。

### 查询

- `campaign` 查询多了 `army`（部队名册、伙伴的伤痕和被俘、与主角的信赖、主角伤势）和 `battle2`：`{phase: none|lineup|active|finished, scene, template, scale, act, over, lineup, view, result}`。
  - `lineup`（备战时）：`candidates`（招募了、活着、没被俘的伙伴：`id, name, cls, hp, max_hp, scarred, fated, death_pct, bonds`，另有 `carried_pct`、技能、数值）、`troops`、`protagonist {hp, death_pct, hunters（没揭开是 −1）, available}`、`caps {field, companions}`、`bond_set`。
  - `death_pct`：倒下后没被抬下、仗打赢时的阵亡率（3 枚，宿命之地 1 枚）；`carried_pct`：被抬下时的阵亡率（没伤痕又不在宿命之地是 0）。
  - `view` = `BattleRules.view(state)`，`result` = `BattleRules.result(state)`（结算后）。
- `campaign.battle2`：同上的 `battle2`；`campaign.battle_preview` = `BattleRules.preview(state)`（没在打仗时 `{ok: false, err: "no_battle"}`）。
- 合同 §7.5 规定所有查询结果里不许出现隐藏键黑名单（`CardViewModel.FORBIDDEN_KEYS`）。内核视图和预演里有 `units`、`tags` 两个键，所以交出去前统一加前缀 `battle_`：`view.battle_units`、`enemies[].battle_tags`、预演的 `battle_units`……其余键和内核一模一样（`ocean_battle2.gd` 的 `public()`）。

### 结算规则

- 种子：战役种子 + 场景 id 的 FNV-1a（32 位）。同一局同一场永远是同一场仗、同一组铜钱，读档改不了。
- 开场军心：10；同盟威望 ≥70 时 +1，≤30 时 −2（设计稿“棋盘军心 ≥7 +1、≤3 −2”按十分之一折算）。
- 法郎换进本部金库：法郎 × num / den，向下取整。先令 4/5（25 法郎 = 1 英镑 = 20 先令）；配给 1/2、深海金砖 1/1（按各部期初储备 4000、8000 对 6000 先令折算后取整）。金币、勋章进功能币。主角 ×1.5 等加成都已经在 `result()` 里。
- 伙伴：伤痕 → `scarred = true`，`b_max_hp` = 兵力 − 兵力/4，跨场保留（还没有治疗）；阵亡 → `alive = false`、进 `fallen_companions`、记 `companion_fallen`，和他有关的信赖删掉，远洋羁绊里他那一份也跟着断（只数活着的）；被俘 → `captured = true`，不能出征，大命运选「割让军需赎买」时一并赎回。
- 主角：阵亡 → 本局结束，`ending = "obituary"`、`end_reason = "protagonist_killed"`，讣告文字在 JSON（不是四个结局之一，回忆录署名是活着的伙伴）；倒下活下来 → 重伤，下一场不能上，坐过一场就好；打赢且打完仍在场 → 同场活下来的伙伴与主角的信赖 +1（最多 3），下一场作为 `bonds_trust` 交给内核（护卫铜钱）。
- 战败（军心归零）→ 大命运待处理，`trigger = "battle_lost"`；主角在场时战败 → 被俘，`trigger = "protagonist_captured"`。沿用 `campaign.big_fate`。撤出不转大命运。
- 部队：本场溃散过的 −1 格编制，到 0 解散（记 `troop_disbanded`）。新开局按这一部的起始部队给名册；进入新的一部时按那一部的起始部队补齐（按兵种数）。

### 流程

1. 白天打出手里的「战场」牌。牌视图的 `panel` 由 `ocean_battle2.gd` 的 `card_panel()` 决定：备战 → `battle_lineup`，在打 → `battle_v2`，打完没结算 / 结算过 → `battle_result`。
2. 出征名单：打开时还没有本场名单就发 `campaign.battle_prepare {}`。一行一个伙伴（兵种字、兵力 / 伤痕、宿命之地、倒下阵亡率 `death_pct`（抬下 `carried_pct`）、他点亮的阵营羁绊）；主角开关和那一行「军心 +3、奖赏 ×1.5、倒下阵亡 25%、本场猎官 N/?」，「揭开猎官」发 `campaign.battle_reveal {}`；部队在在场上限内勾选；下面列出这份名单点亮的羁绊和档位。默认名单：不在宿命之地的伙伴排满伙伴上限，部队按名册补满在场上限，主角留守。「出征」发 `campaign.battle_begin`，成功就换到战场。
3. 战场：顶栏（战场名、回合 x/上限、军令点和下回合 +N、我方 / 敌方军心条、在场人数、皇帝的命令）；左栏羁绊（数量 / 下一档，生效的标档位）；中间格子；右栏来敌（之后 2 回合，暗影密使 3 档 3 回合，猎官 / 精英等标签）和情报（悬停）；下面部署栏、军令手牌、上一轮交火日志、按钮。
   - 格子上：地形像素块（平地、高地、道路、村庄、树林、河、桥、浅滩、沼泽、红门、鹰旗、胸墙），路线是一串小方点，预留炮位红虚框。我方单位是蓝底方块加兵种字（伙伴和主角金边、名字在上），朝向小三角，兵力条；濒死变灰打红叉；方阵双框；技能充好有金点。敌人红底加敌种字，精英金边，重装粗边，猎官靶心，处决骷髅，兵力条；一格最多 2×2 个。
   - 敌情（每回合交火前画好）：移动箭头（沿路线）、攻击红线（远程虚线）和伤害数、冲进鹰旗的 −N、炮击准星（本回合实线，下回合淡色加「下回合」）、处决骷髅 / 猎官靶心 / 斩首标记、被先手打掉的意图灰色虚线；下回合要来的波次在红门上标 +N。
   - 操作：点部署牌 → 亮着的格子 → 四个小箭头选朝向（悬停箭头预览射程）；点格子上的单位 → 撤下 / 技能（点名、筑垒要再点目标格）/ 结方阵或解除 / 瞄准（炮兵）/ 抬下（濒死）；点军令牌，要目标的再点一行、一格或一个单位；主角牌上的「后方调度」；交火、撤销、换牌（再点一张牌）、撤退（确认）。Esc 先退出当前操作，再关面板（仗不会丢，再打出战场牌回来）。
   - 悬停单位或敌人：右栏写出交火后的兵力和双方军心（`campaign.battle_preview`），格子上的兵力条把要掉的那段标成黄色。
   - 打完：格子上出胜负横幅和「查看战果」。
4. 战果：胜负、胜利方式、星级、奖赏（法郎换成本部币制的数目来自 `battle2.payout`）；倒下的人逐个播铜钱（快动画或「跳过动画」时直接翻开），写出活下来留伤痕 / 阵亡 / 抬下只留伤痕 / 被俘；溃散的部队、信赖 +1。「继续」发 `campaign.battle_finish {}`；输了就关掉面板并打开手里的大命运牌（原来的大命运对话）。
5. 为了让界面按钮知道能不能按，内核视图加了几个字段：单位 `can_withdraw`（本回合刚部署的不行）、`can_carry` / `carry_cost`（相邻有人、军令点够；军医相邻免费），部署栏主角 `can_dispatch`（后方调度）。抬下的军令点算法抽成 `_carry_cost`，规则不变。
6. `campaign.battle2` 查询多了 `payout`（换算后的储备、币名）、`resolved`、`has_battle`、`panel`；打完没结算时就带 `result`（铜钱由种子定，打完以后谁也改不了）。出征名单多了战场名、规模、回合上限、敌军心、皇帝的命令、情报币数。

### 剧情门槛（不会卡死）

- `ocean_campaign._choice_error`：推进剧情的选项（`advance` 不是 false）在本场的仗了结之前返回 `battle_pending`；剧情牌上这些回话变灰，理由「先打完本场的仗：在营地点「排兵出征」」。鉴定、挂牌、街区等不受影响。

## 3D 战场（明日方舟式斜俯视，2026-11-01）

`battle_board.gd` 原地重写：对外接口和以前的 2D 格子一样，`battle_panel.gd` 一行没改。主人要的样子是“不再是像素风，战斗像明日方舟的战役界面”，这一片只做战场本身（地图、单位、敌情、高亮）；部署卡条、费用、单位信息栏、技能 / 撤退按钮这些 HUD 由下一片在 `battle_panel.gd` 里做。只借布局，不用别家的素材、图标、字体。

### 文件

- `scripts/cards/ui/battle/battle_board.gd`：板子本身（Control）。搭场景、同步视图、每格的透明按钮、对外接口。
- `scripts/cards/ui/battle/field/`（都没有 `class_name`，preload）：
  - `field_cam.gd`：相机和投影。俯角 54°、竖直视角 30° 的透视相机；`fit()` 把整张图（各格顶面、四边底座、最后一排小人的头顶和血条）迭代缩放、平移到安全区正中；`project()` 和 `Camera3D.unproject_position` 一模一样（测试对过），不进场景树、无头模式也能用。
  - `field_terrain.gd`：地块网格。每格一块有厚度的板：平地类顶面 0.18，高地 / 胸墙 0.5，河 0.03、浅滩 0.085、沼泽 0.11（往下沉，顶面就是水面，河和浅滩的水会慢慢流）；相邻高低不同的地方补侧面，整张图四周有一圈往下到 −0.42 的底座。同一种贴图的格子合成一个网格。桥：顶面是河水，人站在桥面（0.18）上，`prop/bridge` 原点放在水面。
  - `field_props.gd`：摆件和小人占位（见下）。
  - `field_unit.gd`：一个单位的 3D 节点：逐帧图或兵人、脚下软影子、阵营圈、我方的朝向箭头、动画。
  - `field_shaders.gd`：两份着色器。地块顶面（贴图、每格明暗微差、格线、水面流动）；地面记号（圆角格、软圆、阵营圈、炮击准星、路径带、箭头），全用距离场 + `fwidth` 抗锯齿。
  - `field_overlay.gd`：上面的 2D 叠加层（按相机投影后再画，字和线在任何分辨率都清楚）。
  - `field_backdrop.gd`：远景。有 `bg/battle_backdrop` 就铺满裁切，没有就画夜空到薄雾的渐变、三层远山、硝烟带、地图后面的暖光。

### 怎么渲染

- 板子里放一个 `SubViewport`（`own_world_3d`，4×MSAA），按窗口实际像素渲染（1080p 窗口是 1.5 倍，最多 2 倍），用一个 `TextureRect` 缩回板子大小显示，所以 1080p 上地块边、兵人、记号都不糊。远景放在视口里的 `CanvasLayer(-1)`，环境背景 `BG_CANVAS`，3D 画在它前面（地块边缘的抗锯齿是对着远景混的，不会有黑边）。主光从左上前方来、补光从右后方来，环境光偏冷。
- 叠加层（`Overlay`）和格子按钮（`Cell_c_r`）在视口上面，都在板子的本地坐标里。板子根节点调了 `HdTheme.apply_hd_filter`；旧的像素界面和项目设置都没动。
- 默认安全区：板子满屏（宽 ≥ 1000 且高 ≥ 600）时上 64、下 170、左右 24 给 HUD；小板子（嵌在现在面板 900×392 的格子区里）只留 8 像素窄边。HUD 那一片把板子铺满全屏后调 `set_safe_area(rect)` 给自己的区域就行。坐标字母和数字从安全区里扣地方（左 20、下 22）。

### 对外接口

和以前一样的：信号 `cell_pressed / cell_hovered / cell_left(col, row)`；`set_view(v)`；字段 `view valid_cells target_cells pattern_cells selected hovered ghost_hp doomed cols rows cell origin`（`cell` 是中间那格投影后的大小，`origin` 是整张图投影后的左上角，只为兼容）；`queue_redraw()`（面板改完高亮就调它，板子在 `_draw` 里把高亮同步到 3D 和叠加层）；`cell_rect(c, r)`（这一格顶面投到屏幕上的外接矩形，面板用它摆朝向箭头和动作菜单）；`cell_center(c, r)`（顶面中心的投影）；`cell_button(c, r)`；`enemies_at(c, r)`。

新加的：`set_safe_area(rect: Rect2)`、`safe_area() -> Rect2`、`cell_quad(c, r)`（顶面四角的投影：后左、后右、前右、前左）、`cell_top(c, r) -> Vector3`（顶面中心的世界坐标）、`unit_node(key)`（`"u:<uid>"` / `"e:<编号>"` 的 3D 节点）、`unit_data(uid)`、`hero_on_field()`、静态的 `art_id_for(unit, enemy)`。

### 输入

每格还是一个按钮 `Cell_<列>_<行>`（测试按名字点它们），透明，`_has_point` 只认这一格顶面投到屏幕上的四边形（`Geometry2D.is_point_in_polygon`）；格子上站着人或敌人时多边形再往上包住人身的下半截（凸包），点人也算点这一格。前排的按钮加得晚、压在上面，点哪算哪，相邻格子的外接矩形重叠也不会点错。

### 美术怎么接（放了图不用改代码）

- 地块顶面 `tile/<tex>.png`：`HdArt.terrain_tex(地形)`（清单里没写时按 plain/gate/eagle → grass、road、high → rock、village → village_ground、woods → forest_floor、river/bridge → water、ford、marsh、earthwork → earthwork_top）；侧面 `side_rock`（高地、胸墙）/ `side_earth`（其余）。没有图就是 `HdPlaceholder.make_tile_tex` 的无缝噪声贴图（每种地形自己的两种颜色，高地明显偏灰偏亮）。
- 摆件 `prop/<id>.glb`：树林每格 2–3 棵（后两角放 tree_a / tree_b，前角放 tree_c，人站中间不挡）、村庄一栋 house_a / house_b、高地一半格子放 rocks、沼泽 2–3 丛 reeds、红门 gate（放在格子靠 +X 的一边，门洞朝 ±X）、鹰旗 eagle、桥 bridge（两边不是河就沿 X，否则转 90°）、胸墙 earthwork（转 90° 放在敌人来的 +X 一边）、平地四格里约一格放一丛小灌木；拒马（工兵放的 barricade 单位）用 cheval。没有模型就是代码搭的低多边形。
- 小人 `unit/<id>/<state>_NN.png`：主角 `villefort`；伙伴用自己的 id（`dantes`、`gourgaud`……，单位视图的 `uid` 就是伙伴 id），伙伴没有自己的图时退回 `troop_<兵种>`；部队 `troop_<cls>`；敌人 `enemy_<kind>`。`Sprite3D` 竖直、绕 Y 轴朝相机（`BILLBOARD_FIXED_Y`），一帧 384 像素高对应 1.3 个格，竖向再拉 1/cos(俯角)（竖直的纸片从斜上方看会被压扁，拉回来后屏幕上的比例和画里一样），脚底锚点 `(192, 336)` 对准格子中心，朝左时水平翻转，按 `meta.json` 的帧率播放；同一格几个敌人时缩小错开站。没有图时是“兵人”：底座、腿、上衣、头，按兵种换帽子（双角帽、筒帽、熊皮帽、骠骑兵皮帽、头盔）和家伙（火枪、线膛枪、马刀、药箱、鼓、斧子），骑兵连马、炮兵连炮、弹药车；我方蓝衣、敌方红衣，主角金肩章金腰带，伙伴系自己强调色（`HdArt.accent`）的腰带和帽羽。
- 远景 `bg/battle_backdrop`。

### 画面上有什么（和以前的 2D 格子一样多，一样都没少）

- 地形（高低、贴图、摆件），格子线，A–I / 1–5 坐标（字母在前沿下面、数字在左边）；炮位：虚线框 +「炮位」；红门：地面红框 + 门；鹰旗：旗杆三色旗。
- 路线：每条路线一串贴地的圆点。敌人这一回合的移动：沿路线的橙色带子 + 箭头（被我方先手作废的是灰色虚线，敌人身上再画一个灰叉）。
- 我方单位：脚下阵营圈（部队蓝、伙伴浅蓝、主角金）、金色朝向箭头、血条（交火后会掉的那截标黄）+ 兵力数字、兵种徽章、主角和伙伴的名字牌、技能就绪的金菱形、方阵图标；濒死：人半跪发灰、圈变灰、血条旁「濒死」；本回合交火后会倒下：圈变红闪、徽章边上骷髅、血条红框。
- 敌人：红圈（精英金圈、精英和重装圈更粗）、血条 + 数字（悬停预演时标黄）、种类徽章、猎官靶心（主角不在场时画淡）、处决骷髅；同一格几个敌人叠成一张小卡，每人一行。

- 高亮：能部署的格子（平地绿、高地蓝）、目标格红、射程 / 冲锋路线橙色虚线框、选中的格子金框（轻闪）、悬停白框。

### 动画（只是表现，逻辑不等）

新单位从上面落下来；挪了格子滑过去；兵力少了闪红、往后一抖；没了就沉下去缩小再删；兵人待机轻轻起伏。无头模式下不建补间，测试和自动试玩不受影响。

交火回放（2026-11-01 修订）：回合数变了（交火过）时不再一下子全放完，而是按步放，每步约 0.42 秒（`STEP_S`）：
① 射程里有敌人的我方单位往前冲（开火、白刃）；② 敌人挨打闪红、头顶飘金色「−n」，被打死的倒下；③ 敌人移动；
④ 敌人往目标冲、我方挨打闪红、头顶飘红色「−n」，我方倒下 / 濒死；⑤ 冲进鹰旗的敌人走到鹰旗格再倒下，鹰旗上飘「军心 −n」
（文字 `float_morale`），新来的敌人这时才落下。伤害数从上一份视图和这一份视图的兵力差算（`_prev` 对 `view`），冲进鹰旗看
上一回合敌情里 `attack.kind == "eagle"` 的敌人。回放时下一回合的敌情（3D 路线箭头、攻击线、伤害签）先藏着，放完再亮。
放的时候玩家点了任何东西（部署牌、格子、军令牌、交火、撤退）或者来了新视图，剩下的几步立刻放完（`skip_playback()`），
不挡操作；`is_playing()` 告诉面板还在放。无头模式不回放，节点一下子到位（测试读到的位置照旧）。

第二轮评审修正：同一格的敌人数目变了（合到一格、同格的倒下、新来的落进来）时，小人缩放跟着变（`STACK_SCALE`），以前是删了重建，
重建的被当成新来的藏到最后一步，走位和挨打飘字都丢了、旧的那个凭空消失；现在同一个节点换大小（`field_unit.gd` 的
`set_token_scale`，整个节点按比例缩放，头顶高度跟着改），缩放放在第 ③ 步（和走位一起）。叠加层回放时跟着小人走：
叠在一格的敌人小卡锚在这几个小人现在站的地方（平均），兵力条和数字画“回放放到哪一步”的兵力（节点 meta `shown_hp`，挨打那一步才降，
`board.shown_hp()`）。面板顶栏的回合数、军令点、双方军心和战报在回放放完（`playback_finished` 信号，或被跳过）之前停在交火前那份视图。
叠在一格的敌人小卡压住后面我方单位的身子时往左或往右挪开（`_clear_allies`）。

### 给 A 的接口（先交付的部分）

|---|---|

常量照旧能读：`SCALES`（多了 `grand`、`epic`）、`TERRAIN`、`TERRAIN_CHARS`、`TERRAIN_NAMES`、`GROUND`、`HIGH`、`TOP`、`ENEMY_WALK`（旧成员在前、顺序不变）、`ENEMIES`（111 种）、`LEVELS`、`WEATHERS`、`KNOWN_TAGS`。其中 `SCALES / TERRAIN_NAMES / GROUND / HIGH / TOP / ENEMY_WALK / ENEMIES` 现在是 `static var`（要拼上 JSON 里的行），别处只能在运行时读，不能写进别的脚本的 `const` 表达式。

`new_battle(tpl, setup)` 的 setup 新增（类型不对返回 `{error: "bad_setup", errors}`）：

- `level`：整数 1–24。没给时取 `2·act − 1`；只给 `level` 时 `act` 取 `(L+1)/2`（只作显示）。
- `weather`：8 种之一。没给时取模板 `weather` 候选的第一个，再没有就是 `clear`。战役层应自己用 `pick_weather` 挑好再传。
- `mods`：`{cp_bonus 0..4, enemy_morale −4..0, prep_turn 0..1, drop_waves:[模板波次下标], terrain:[{cell, terrain}]}`。`terrain` 先改模板副本的地图再校验（改坏了路线会返回 `bad_template`）；`drop_waves` 按模板里原来的下标删波次；`prep_turn = 1` 多一个准备回合：所有波次、炮的第一炮、地形事件、坚守目标、路线时效都晚 1 回合，回合上限 +1（最多 20）；`cp_bonus` 加在开场军令点上（和原来的 `cp_bonus` 分开夹）；`enemy_morale` 在按等级放大以后再加（至少留 1）。
- `roster[].from_turn`：伙伴第 N 回合起才能部署（C28）。之前部署返回 `not_yet`，部署栏 `reason: "not_yet"`、`from_turn: N`。

**兼容（硬规矩）**：setup 只给 `act`（没给 `level`、`weather`、`mods`）的仗，状态、日志和 `result()` 都和第五片之前逐字节相同——远洋单段书的 `hash_v1` 连 `rogue.battle2.state` 一起算，所以单段书的战役层**不要**传 `level / weather / mods`。给了其中任何一个就是「新式」的仗：状态多 `level / weather / loot / ransom / killed_kinds` 五个键，开场日志换成带 Lv 和天时的那句，`result()` 多 `level / weather / killed_kinds / loot / ransom`。`level = 2a − 1` 的新式仗和第 a 幕的旧仗除了这五个键和开场那一句，状态、日志、结算完全相同（测试逐模板对过）。读 `result` 的新字段一律用 `get(键, 默认)`。

`view()` 新增：`level`、`level_stars`、`weather`、`weather_name`、`weather_desc`（旧仗按 `2a − 1`、`clear` 算）；`grid.cells[]` 加 `tier`（层：虚空 −1、水 0、地面 1、高地 2、墙 / 桅杆 / 桅盘 / 屋顶 3）、`los`（这一格挡视线）、`stand`（我方站位 ground / high / top / none）、`dark`（黑暗格，夜战时每一格）；`deploy_bar[]` 加 `top`（这个兵种能上顶层）、`from_turn`；`enemies[]` 加 `hidden`。隐身的敌人在 `enemies[]` 里是 `kind / type: "unknown"`、名字是「？」、`hp / max_hp / atk / def / spd` 为 0、`tags` 为空；`intents()` 里同样隐去，波次条里还没出场的隐身兵也一样；`preview()` / `preview_cmd()` 对它只给 `{alive, hidden: true, dmg, col?, row?}`，不给兵力。

`result()` 新增（只在新式的仗里）：`killed_kinds {兵种: 数量}`（击杀、落水、坠落都算；战役层的 `kill_flags` 看它）、`loot`、`ransom`（法郎 −15%/个、金币 −1/个的扣减在战役层做）、`level`、`weather`。主角被 `arrest` 敌人的白刃打倒时，`fallen` 里主角那一行是 `{captured: true, arrested: true, rolled: false, coins: 0}`，`captured` 里有 `hero`（新旧仗都一样）。

### 等级

- `LEVELS` 就是 §8.1 的表（下标 L−1），奇数行 L1/3/5/7/9/11 等于原来的 `ACT_HP_PCT / ACT_MORALE_PCT / ACT_ATK_BONUS`（这三个常量只为兼容保留，内核不再读）。运行时只用前四列：敌兵力 %、敌军心 %、敌攻 +、敌防 +；攻、防的加成只加在原值大于 0 的敌人身上。猎官 / 精英 / 回合三列是模板编写目标，`lint_template` 提醒，不硬改。
- 名额：开战时按 `caps(scale, L)` 定。grand、epic 在 L ≤ 11 的名额数组是本稿补的（设计稿只给了 L ≥ 12），和 L12 接得上：grand 在场 8/8/9/9/10/10、伙伴 4/4/5/5/5/5；epic 在场 9/9/10/10/11/11、伙伴 5/5/5/6/6/6。
- 新规模 `grand`（大会战，默认 10×6，法郎 260，勋章 4，金币 1）、`epic`（决战，12×7，320，5，2）。皇帝的命令、主角的「会战 +2 勋章」对 major / grand / epic 都算。
- 模板 `size: [cols, rows]` 覆盖规模的默认尺寸，5×3 到 12×7；地图行数、列数要和它一致。
- `lv_min`（波次或单个兵）：L 不到就不出；旧的 `act_min = a` 按 `lv_min = 2a − 1` 算。整波被筛空就不来（也不占纵队编号）。
- `base_level: b` + `pad: {kind, every}`：每一波**走路线的**兵补 `max(0, (L − b) / every)` 个 `pad.kind`（炮位、定点射手的波次不补）。`pad.kind` 必须是走路线的兵种。
- 斩首令：L ≥ 7，不在遭遇战（原来是第 4 幕起，等价）。
- **没写 `level` 也没写 `base_level` 的模板只认第一幕奥军 7 种**：旧 7 张就是这样，`test_battle_v2` 要求这种模板里写 `cossack` 报「unknown enemy」。新名册的兵只给写了等级的模板用（错误信息会提示）。
- 奖赏缩放（napoleon 书法郎 ×(100 + 4(L−1))/100、分支 Boss 勋章 +1）在战役层做，`result()` 的奖赏不变。

### 地形

`TERRAIN` 表就是 §9.1（40 种，含胸墙）：`ch / stand / walk / cost / def / rdef / los / tier`，外加 `start`（红门、舱口、牢门）、`end`（鹰旗）、`dark`（牢廊、墓穴）、`spawn`（村庄、树林、跳板、街道、墓穴）。`GROUND / HIGH / TOP / ENEMY_WALK` 由表推出，`can_stand` 也只看表：ground 给 place = ground / any，high 给 high / any，top 只给 `CLASSES[cls].top`（现在只有猎兵，猎兵兵种的伙伴自动算），none 谁都不行。不认识的地形谁都不能站、不能走。

- **防**：`def` 对双方都加（村庄、房屋 +2，瓦砾、牢房 +1）；`rdef` 只在挨远程（射击、炮击）时加（树林、洞穴 +2）。旧地形数值不变。
- **步耗**：敌人沿路线每走进一格扣这一格的步耗（瓦砾、雪地、泥地、浅水 2，其余 1）。速度不够时停下，**剩下的步数存进敌人的 `mp`** 留到下回合（不然速度 1 的步兵永远进不了雪地）；被挡住、被猎官停下、被击退时清零。下一格此刻走不了（门锁成墙、冰裂成河）就停在原地等。旧地形全是 1，`mp` 不会出现。
- **视线**：小火器（我方横队、猎兵；敌方 range > 0 且不是炮的）要视线，炮是曲射不看。整数 Bresenham：沿长轴逐格走，正好落在两格中间时缓线取行号较小的一侧、陡线取列号较小的一侧；两端之间（不含两端）有一格挡视线（墙、桅杆、洞穴、房屋）就不通。我方横队、猎兵的射程是一条直线，所以等价于「图样在第一个挡视线的格子截断，那一格本身还打得到」：站在房屋、洞穴里的单位能往外打，打得到洞里的敌人，打不到洞后面的。敌方远程锁定目标和出手时都要求视线通；被挡住时照旧打挡住它的那个单位。
- **虚空** `_`：不属于战场。射程图样跳过它（后面的格子照样算）、不挡视线、冲锋到这里停、不能在路线上；视图里 `tier = −1`。
- **顶层**（层 3：桅盘、屋顶）：站在上面的横队 / 猎兵射程 +1（敌方桅顶射手同理），打层 ≤ 1 的目标攻 +1（双方都是）。敌炮选目标时把顶层当高地（排在地面单位后面）。
- **黑暗**（牢廊、墓穴；夜战时每一格）：射手站在黑暗格上射程 −1，最少 1；我方炮兵的图样也短一列（2–4）。敌炮不受影响。
- **洞穴**：敌炮不瞄洞里的单位；洞里挨远程防 +2（双方）。
- **事件改地形时格子上有人**（`_begin_turn` 里改地形之后、`on_kill` 改地形之后都处理）：我方单位脚下变得站不住（冰裂、涨潮）退回部署栏、冷却 2 回合，不算倒下、不扣军心、不退军令点；濒死的伙伴按「已被抬下」处理；拒马直接没了。敌人脚下走不了（走路线的按 `walk / start / end`，站 at 格的按它的 at 地形）就移除：按击杀扣敌军心、记 `kills` 和 `killed_kinds`，日志写「落水」（变成层 0 的格子）或「坠落」。旧模板的事件只会把河变成浅滩，碰不到这些。
- **击杀改地形**：`events: [{"on_kill": 敌兵种, "cell", "terrain"}]`。打死这种敌人（任何方式）时上膛，在这一回合交火的 e 步、清点完阵亡之后改地形，只触发一次；之后照常处理格子上的人。路线起点被封死（不再是起点、也不是能站的可走格）时，之后从这里出的波次不来了，日志写一句。
- **出生格**：路线起点必须是红门、舱口、牢门；这条路线上**每一波、每个兵**都带 `ambush` 或 `boarder`（兵种自带或模板给的）时，起点还可以是模板 `spawns` 里列出的伏兵格（`spawns` 只能列村庄、树林、街道、墓穴、跳板），或者任何跳板。还没出的波次要用的伏兵格、跳板和炮位一样算「预留」，不能部署。
- **路线时效**：路线可以写成 `{"cells": [...], "until": 回合}`（或模板的 `route_until: {路线: 回合}`）。校验器只查「首次使用」到 `until + 路线长度` 这几回合的地形，并且拒绝 `until` 之后还走这条路线的波次。没写 `until` 的照旧查首次使用和最终地形两个时刻。按规格这个窗口包括起点：锁门的事件要晚于 `until + 路线长度`。
- **at 格**：炮和带 `post` 的定点射手站 at 格，不在任何路线上。允许的地形：兵种的 `at_terrain`，没写的是高地或平地；`boat` 只能在海上，`top` 只能在顶层。走路线的兵不能站 at 格，`post` 不能走路线。
- **骠骑兵冲锋**：前方 3 格（骑兵预备队 +1、泥泞天 −1）；遇到站不住的格子（虚空、墙、河、海……）或预留格就停在它前面，冲进泥地就停在泥地上，这样够不着后面的敌人就不冲。
- 模板校验另外认这些新键：`level`、`base_level`、`pad`、`weather`（字符串或数组）、`spawns`、`kill_flags {敌兵种: 旗标}`、`objective`（字典）、`tutorial`（布尔）、`route_until`；`order_next` 和三包草稿里的 `notes / plan / segment / node / date / fated / order_fallback` 等键一律忽略。红门（和牢门）现在允许出现在路线中途（规格：「起点 / 途经」）。

### 敌军

- `ENEMIES` = 旧 7 种（逐字节不变）+ `battle_enemies.json` 的 104 种，形状 `{name, hp, atk, def, spd, type, range, tags, at_terrain?, move?}`，数值是 L1 基线，出场时按 `LEVELS` 放大。
- 内核认识的标签（`KNOWN_TAGS`，模板里写别的标签校验报错）：
  - `pierce`：挡住它要多 1 个空余阻挡位（普通 2、重型 3），占用照常。
  - `skirmisher`：c 步接了白刃（被挡住或在打主角）还活着，下一回合 b 步先后退 1 格并脱离阻挡（这一回合不再前进）；每 2 回合最多一次（记在敌人的 `skirm_turn`）。
  - `ambush` / `boarder`：见上面的出生格。
  - `post`：定点不动的远程，用 at 波次出场；照常锁定、射击。
  - `top` / `boat`：at 格的地形限制。
  - `stealth`：离我方所有在场单位（濒死的算，拒马不算）都超过 2 格时，视图、敌情、波次条、出场日志、我方射击日志里都是「？」；规则不变。
  - `loot` / `ransom`：走进鹰旗时照常扣军心，另记 `state.loot / state.ransom + 1`，各写一句日志。
  - `arrest`：主角在它的白刃下倒下（兵力从正数打到 ≤ 0）时不掷铜钱，直接被俘。
  - `rally`：同纵队攻 +2，取代纵队长原来的 +1。
  - `short`：炮只瞄与自己列差 ≤ 4 的单位。
  - `rocket`：打准星格，同时以半伤（至少 1）打准星格靠鹰旗一侧（列号 −1）那一格；敌情的准星行带 `splash`。
  - `sniper`：远程挑目标时先挑主角和伙伴（再按距离、兵力）。规格里的「其次精英和军官」在我方没有对应的分类，没做。
  - 旧的 `hunter / heavy / officer / execute` 不变。

### 天时

`state.weather`（新式的仗才有这个键；没有时按 `clear`），开战时定下，战斗中不变：

| 天时 | 规则 |
|---|---|
| clear | — |
| rain | 双方小火器攻 −1（伤害至少 1）；炮、我方炮兵、点名不受影响 |
| mud | 敌骑兵每格步耗 +1；骠骑兵冲锋距离 −1 |
| snow | 每回合军令点 −1（3 → 2）；军医回复 −1（3 → 2） |
| fog | 来敌提前公开的回合数 −1（2 → 1；情报 3 档 3 → 2） |
| night | 每一格都是黑暗格（射程 −1，最少 1）；来敌提前公开 −1 |
| desert | 第 3、6、9……回合的 e 步（治疗之后）：我方在场单位本格和上下左右都没有水井的兵力 −1，最低留 1 |
| storm | 每回合 e 步（充能之后、判胜负之前）：站在桅盘上的我方单位兵力 −1，最低留 1；带 `boat` 的敌炮开一炮后隔 3 回合（平时 2） |

### 和规格不一样、或者规格没写死的地方

1. 步耗的「速度不够就停在原地」加了余步结转（上面「步耗」一条），否则速度 1 的兵进不了步耗 2 的格子。三包草稿的模拟器也是这么做的。
2. `ambush` 的「从 `spawns` 出生」做成「这条路线的起点是 `spawns` 里的格子」，不另加出生机制；同一条路线上不能混不带标签的兵。
3. 隐身敌人在我方射击日志里也写「？」（打死的那一句写真名）。
4. `mods.prep_turn` 整条时间线晚一回合（规格只说「第一波晚一回合到，回合上限 +1」）。
5. 新式仗的开场日志换成带 Lv、天时的一句（battle_text.json `log.open`）；旧仗不变。
6. 新键只在新式仗里出现（兼容那一条）；`from_turn`、`mp`、`skirm_turn` 也只在用到时才写进状态。
7. 视线平局：陡线（行差大于列差）取列号较小的一侧（规格只写了缓线取行号小的）。
8. 三包草稿里伊夫堡的三张图（`catalans_cove` 的 `extract`、`marseille_arrest` 的 `protect`、`if_corridors` 的 `escape`）命令类型内核不认，校验不过；按 C18 由 C 的合并脚本改成 `hold / no_leak`、原提案进 `order_next`。其余 35 张草稿用这一版内核全部校验通过、能打完、什么都不做必输（scratch 探针，B2 合并时再用正式测试过一遍）。
