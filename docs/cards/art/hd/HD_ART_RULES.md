## 1. 目标画风

**要的是“三渲二”**：在 Blender 里做 3D 模型，用卡通着色（toon shading）加描边渲成像手绘的 2D 图。

- **剧情对话**：做成视觉小说，每句话配人物大立绘、全屏背景、名字牌和文本框。立绘要有清楚的脸（眼睛、眉毛、嘴）、手、服装细节，表情能看出区别。
- **战斗界面**：斜俯视的格子战场，地块有高低，上面站着小人。小人和立绘用同一个人物模型、同一套配色，玩家一眼认得出是谁。
- **时代**：1796–1835 年。法军是深蓝、白、红配金；奥军是白色；英军是红色。服装按历史大致来，不要求考据到纽扣。
- **着色**：
  - 2–3 阶色带（Shader to RGB + ColorRamp 设成 Constant），不要写实材质。
  - 描边用深褐色，不用纯黑。可以用 Line Art，或者 Solidify 反向外壳。
  - 色彩管理用 **Standard**，不要用 Filmic 或 AgX（会把卡通颜色洗灰）。
- **光**：主光一律从**左上前方**来，再加一道从右后方来的轮廓光。全部图的光向要一致，立绘和小人放在一起时才不打架。

**上次被拒的原因，这次不要再犯**（见 `docs/cards/art/candidates/blender_2026-10-27_all270/REVIEW.md`）：

- 镜头里只拍到墙或地板、东西不在画面里的空图；
- 没有脸、没有手、像棋子或木偶一样的人物（`art/ocean_3d` 里那批 128 像素的小人就是这种，不能用）；
- 用方块拼出来、一眼看得出是方块的房子和家具；
- 透明底的图上带了一圈地面阴影或雾；
- 图里有文字、水印、签名或 logo。

**不能抄**：

- 不用《Fate/Grand Order》《明日方舟》或任何其他游戏里的素材、图标、logo、角色设计，也不描摹它们的画面。我们只借“视觉小说 + 斜俯视塔防”这种通用的版式。
- 不用从商业游戏里扒出来的模型（全面战争、拿破仑题材游戏等）。

## 2. 通用技术规定

| 项目 | 规定 |
|---|---|
| Blender 版本 | 3.6 LTS 或 4.x 都行，每批在 `BATCHES.md` 里写明用的版本 |
| 渲染器 | EEVEE（快，适合卡通着色）；Cycles 也行 |
| 色彩 | sRGB，8 位；色彩管理 Standard，曝光 0 |
| 透明底 | Film → Transparent 打开；导出 PNG RGBA，**直通 alpha（不预乘）**；边缘不要有黑边或白边 |
| 尺寸 | 严格按清单 `kinds` 里的像素尺寸，不能多也不能少 |
| 文件大小 | 按 `kinds.max_kb`；PNG 可以用 `oxipng -o 3`（无损）压一下 |
| 禁止 | 文字、水印、签名、logo、相框；AI 生图（Imagen 等）直接当成品交 |

**为什么尺寸是这样**：游戏按 1280×720 排版，但在 1080p 和更高的屏幕上会按屏幕分辨率清晰渲染。所以全屏背景按 1920×1080 出，其他图也都按 1.5 倍以上出。

## 3. 目录和文件名

全部放在 `art/hd/` 下。id 必须是清单里有的，全小写。

| 类别 | 路径 | 尺寸 | 底 |
|---|---|---|---|
| 背景 `bg` | `art/hd/bg/<id>.jpg`（或 `.png`）；变体用 `<id>__<变体>.jpg`，比如 `jamestown_shop__night.jpg` | 1920×1080 | 不透明 |
| 结局插图 `cg` | `art/hd/cg/<id>.jpg` | 1920×1080 | 不透明 |
| 剧情立绘 `chara` | `art/hd/chara/<人物id>/<表情>.png`，表情只能是 `normal` `smile` `angry` `sad` `surprise` | 1200×1800 | 透明 |
| 头像 `face` | `art/hd/face/<id>.png` | 512×512 | 透明 |
| 战场小人 `unit` | `art/hd/unit/<id>/<状态>_<两位帧号>.png`，状态只能是 `idle` `attack` `hit` `down` `dying`，帧号从 `01` 连续；另外可选一个 `meta.json` | 384×384 | 透明 |
| 地块顶面 `tex` | `art/hd/tile/<id>.png` | 512×512 | 不透明 |
| 地块侧面 `side` | `art/hd/tile/<id>.png` | 512×256 | 不透明 |
| 地图摆件 `prop` | `art/hd/prop/<id>.glb` | — | — |

**`art/hd/` 下另外只允许三个文件**：

- `SOURCES.csv`：来源登记，见第 6 节；
- `BATCHES.md`：交付记录，见第 5 节；
- `README.md`。

除此之外，任何不认识的文件，验收脚本都会报 FAIL。`.blend` 源文件、中间渲染图、参考图都**不要**放进仓库。

**`meta.json`（可选）** 只允许两个键：

```json
{"fps": 12, "attack_hit_frame": 4}
```

- `fps`：播放帧率，不写就按 12；
- `attack_hit_frame`：攻击动画里第几帧打中（从 1 数），游戏在这一帧弹伤害数字；不写就按攻击帧数的一半算。

## 4. 各类图的要求

### 4.1 背景 `bg`

- 1920×1080，不透明。画面里**不要有人物**，也不要有文字。
- 画面下方约 30% 会被文本框盖住（对照表里会画成阴影）。重要的东西放在中上部。
- **视平线**放在画面高度的 50%–60%，和立绘的机位对得上。室内用 35–50mm 焦距，不要鱼眼。
- 夜景可以暗，但要能看清空间结构。
- `jamestown_shop` 另要一张夜景变体 `__night`（P1）。
- `new_elba_shoal` 另要一张夜景变体 `__night`（P2，第十场开头的午夜海面；没有时剧情先用白天那张）。

### 4.2 剧情立绘 `chara`

**构图**

- 头顶到**大腿中部**；画面下边缘切在大腿上，所以最下一行必须有像素。
- 头顶（不算帽子）在第 **120–200** 行。同一批人物要一致，个子矮的人（小皮埃尔）可以低一些。帽子可以往上伸，但离上边缘至少留 40 像素。
- 人物在画面左右居中。身体可以侧 15–30°，脸和眼睛朝镜头。

**相机**

- 透视相机，焦距 85mm。
- 机位高度在人物胸口，不仰拍、不俯拍，不斜放。

**表情**

- `normal` 必须有，其余四个是可选的 P2。
- 同一个人的各张表情，**除了脸，其他地方逐像素一致**：姿势、机位、灯光、衣服都不能动。只改脸部形态键（shape key）。验收脚本会比对，差异区域超过 20% 就判 FAIL。

**游戏里怎么用**

- 屏幕上站在左、中、右三个位置之一，按高度缩放到大约 680/720。
- 说话的人亮，不说话的人压暗。
- 游戏不会镜像翻转立绘，所以眼罩、伤疤、勋章放在哪一侧都可以。

### 4.3 头像 `face`

- 512×512，透明底，头和肩。脸在画面中央，肩膀切到下边缘。
- 用和立绘同一个模型。可以重新摆机位，从正面略偏一点拍。
- 用在：战斗部署卡、出征名单、战报、敌人信息栏。

**部队头像 `troop_<兵种>`**：画一名该兵种的普通士兵。所有部队头像可以共用一个士兵模型，只换装备。

### 4.4 战场小人 `unit`

**画面**

- 384×384，透明底，**朝屏幕右侧**，游戏里镜像就得到朝左。
- **不要画地面阴影和底座**，阴影、阵营色的圆环、血条都由游戏来画。

**锚点 (192, 336)**

- 双脚之间的地面点必须落在这个像素上。
- 验收时：最低点要在第 326–346 行；脚下的中心 x 要在 132–252 之间。
- 每一帧都要对准锚点，**包括倒地帧**：躺下的人贴着这条地面线。

**相机**

- 正交相机，从水平往下俯 **25°**。
- 人物转向屏幕右侧，再朝镜头转 30°，也就是 3/4 侧面。

**大小**

- 单人站立时，头顶到脚底约 **200–260 像素**。
- 骑兵、炮可以宽一些、高一些，最多 320 像素高，但不能出界。

**组成**

| 谁 | 画什么 |
|---|---|
| 主角、伙伴 | 单人；骠骑兵连马，炮兵连炮 |
| 部队 `troop_*` | 3 名士兵前后错开站成小队形；骠骑兵画 2 骑；炮兵画 1 门炮加 2 名炮手。整体仍然以锚点为中心 |
| 敌人 `enemy_*` | 单人；炮和弹药车按清单描述 |

**状态和帧**

每个状态**至少 1 帧**；动画可以以后再补，游戏会用位移、闪白和抖动把静态帧演活。

| 状态 | 画什么 | 建议帧数 |
|---|---|---|
| `idle` | 待机：持械站姿，可以有轻微呼吸 | 1–8 |
| `attack` | 攻击：近战劈刺、开枪、开炮（带火光和白烟） | 2–8 |
| `hit` | 受击：身体后仰 | 1–3 |
| `down` | 倒下：最后一帧躺在地面线上 | 1–6 |
| `dying` | 濒死：单膝跪地或半倒，捂伤口 | 1 |

`enemy_wagon` 不用 `attack` 和 `dying`。

### 4.5 地块贴图 `tex` / `side`

**顶面 `tex`**

- 512×512，**正上方俯视**，四边无缝，可以平铺。
- **不能有方向性**：没有车辙，没有光影方向，没有箭头。游戏会把同一张贴图铺在任意朝向的格子上。

**侧面 `side`**

- 512×256，左右无缝。
- 上边缘是地表（草皮或岩面），往下是土层或岩层。

**区分度和材质**

- 几种地形之间要**一眼分得出**。尤其是高地（`rock`）和平地（`grass`）：高地是放炮兵、猎兵的地方，读错格子就会打错仗。
- 可以用程序化纹理，也可以用 CC0 材质库（Poly Haven、ambientCG）的贴图来改。

### 4.6 地图摆件 `prop`（GLB）

**格式**

- 导出 **GLB**（glTF 2.0 二进制），贴图**内嵌**，**不带灯光和相机**。

**尺度和朝向**

- **1 个 Blender 单位 = 1 格**，一格是 1×1。
- **原点在模型底面中心**，模型立在地面上，最低点 z=0。
- 有方向的东西（桥、胸墙、红门）沿 Blender 的 **X 轴**摆放，游戏会按地图旋转它。
- 每一件的长、宽、高上限写在清单的 `max_size` 里，顺序是 [X 宽, 高, 深]。
- `bridge` 例外：桥墩可以伸到地面以下 0.4。

**面数和贴图**

- 每件 **5000 个三角面以内**。
- 贴图最大 1024×1024，一件最好只用一个材质。

**材质**

- 只用 Principled BSDF 加 Base Color 贴图。卡通效果由游戏的着色器来做，不要在 GLB 里放节点特效。

**用途**

- 树每格放 2–3 棵，由游戏摆位置。
- 房子每格放 1 栋。
- 红门放在敌人入口，鹰旗放在我方要守的点。
- 胸墙、拒马是工兵筑出来的。

### 4.7 结局插图 `cg`

都是 P2。1920×1080，可以有人物，不要有文字。

### 4.8 不用做的

下面这些由代码来画，**不用做**：

- 界面框、按钮、名字牌、文本框；
- 图标（兵种、意图、币、道具）；
- 字体；
- 特效（火光、烟、闪白、伤害数字）；
- 选中圈、射程格、敌人路线。

将来需要图标，会另外出清单。

## 6. 素材来源和许可

每个交付的文件都必须在 `art/hd/SOURCES.csv` 里有一行能覆盖它。`asset_ids` 一栏写路径通配，多个用空格隔开，例如 `unit/marie/* chara/marie/* face/marie.png`。表头固定：

```
asset_ids,source,author,url,license,license_url,notes
```

**`license` 一栏只认下面这些写法**（不分大小写）：

| 写法 | 什么情况 |
|---|---|
| `original` | 在 Blender 里自己建的，或用脚本生成的 |
| `CC0` | Poly Haven、ambientCG、Kenney、Quaternius 等 CC0 素材 |
| `CC-BY-4.0` / `CC-BY-3.0` | 必须写作者，游戏的鸣谢名单里会署名 |
| `public-domain` | 公有领域 |
| `purchased:<商店名>` | 买的，商用许可；`notes` 里写订单号 |
| `mixamo` | Adobe Mixamo 的人物或动作；只能用在渲染里，不能把原文件放进仓库 |
| `mpfb-cc0` | Blender 的 MakeHuman 插件 MPFB 生成的人体，自带资源是 CC0 |

**不行的**：

- 带 NC（不可商用）、ND（不可改编）、SA（相同方式共享）的许可；
- “仅限编辑用途”；
- 来源不明；
- 从游戏里扒的模型；
- 许可没核实过的素材：`art/ocean_3d` 里用到的 NVIDIA SimReady 模型就是这种，核实之前不要用。

**人物模型从哪来**（建议，按推荐顺序）：

1. **主创用 VRoid Studio 捏人**，导出 VRM，再用 VRM Add-on for Blender 导入，由操作方负责服装、姿势和渲染。VRoid 自带的预设可以商用，但每次使用前请先核对 VRoid 当时的使用条款。这样做出来的脸最接近日式立绘，主创亲手捏，许可写 `original`。
2. **MPFB（MakeHuman 插件）生成人体加骨骼**，操作方在上面建服装和头发。脸偏写实，上卡通着色后要调。
3. **买现成的人物模型**，要商用许可，不能有 NC。

**Steam 声明**：

- 场景和构图是 AI 操作方定的，所以这批图上架时要在 Steam 的内容调查问卷里申报“开发中使用了 AI 生成的内容”，这是允许的。
- 以后想撤掉这个申报，要换成由人画或由人摆的版本。

## 7. 验收

**第一道：自动检查**（`check_art.py`）

| 类别 | 查什么 |
|---|---|
| 所有文件 | 尺寸；透明或不透明；文件大小；命名 |
| 图片 | 是不是空图或纯色（亮度标准差、主色占比） |
| 立绘 | 头顶线；下边缘有没有切到大腿；左右是否居中；有没有半透明雾；各表情和 normal 是否只差在脸上 |
| 小人 | 是否踩在锚点上；有没有出界；帧号是否连续；状态是否齐全 |
| 地块 | 接缝；是否纯色 |
| GLB | 是否带灯光或相机；贴图是否内嵌、多大；面数；尺寸；原点 |
| 来源 | `SOURCES.csv` 是否覆盖每个文件；许可是否在白名单里 |

**第二道：放进游戏看**

Claude 合并后，在游戏里截图：剧情对话一屏、出征名单一屏、战斗开局一屏、战斗中一屏。主创看截图决定过不过。重点看：

1. 脸和表情：有没有神，表情分不分得出；
2. 立绘和小人是不是同一个人；
3. 战场上地形、敌我、高低是否一眼读得清；
4. 整体光向和色调是否统一。

**不过就改**，同名覆盖重交。
