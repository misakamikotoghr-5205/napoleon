# 问题模板

标题：`[bug] <任务ID?>: …`

把任务 ID 写成负责的那条线（界面 Cxx、引擎 Gxx、数据 Kxx、指引数据 K16）。拿不准就写最可能的那条，并在正文里写“也可能是……”。

## 正文

- **种子**：
- **存档**：路径（测试必须在 `user://test/<名字>/`，不要用 `user://cards/`）。没有存档就写“新局，未存”。
- **阶段与第几天**：`phase`、`stage`、`stage_day`、`abs_day`。最上面的面板 kind，小游戏 kind（没有就写无）。
- **复现步骤**：指令序列（`command_log` 或 Mock 的 `sent`），或 `autoplay_step` 的步数和命令行（`--engine` `--seed` `--days` `--guide`）。
- **截图**：1280×720，文件名 `<序号>_<阶段>_<面板>.png`。没有显示器就写“无 xvfb，未截图”，改贴当时的节点 / 阶段 / 面板。
- **期望**：
- **实际**：
- **违反哪条红线**（合同 §0 的 1–9，可多选；都不是就写“不是红线，是走查卡住 / 桩”）：
  1. 免 AI 声明（玩家能看到的正文、美术、音频被写成了成品）
  2. 确定性（同一种子两遍哈希不同，或用了登记以外的随机）
  3. 隐藏数值上了界面（概率、百分比、权重、底价、真假、本心、口碑/风声点数、`%`）
  4. 规矩没在戏里讲（弹了机制说明，或新机制没人教）
  5. 鉴定给了结论（小游戏出现“真”“假”“仿”“赝”或等价判词）
  6. 史实措辞（该加“伪”字没加，年份说法不对）
  7. 测试输出里有 `SCRIPT ERROR` / `ERROR` / `WARNING` / `Parse Error` / `FAIL:` / `DATA ERROR` / 退出泄漏
  8. 机制没有新手指引（没有 first-time、没有步骤、没有规矩页，或关掉指引之后局变了）
  9. 打烊永远可用（“打烊 · 下一天”按不到、被某张牌挡住、确认清单和第二天对不上、面板或小游戏关不掉、关掉后又自己弹回来、或者因为时间到了自己往前走）
- **日志最后 20 行**：

```
（贴在这里）
```

## 走查失败时多写这几行

- 哪一步没亮，或 `shown_log` 和 `_test.d1_3` 从哪一个 id 开始不一样
- 当时阶段、开着的面板
- `CardAnchors.ids()` 里这一步的锚点在不在
- 归谁：K16（步骤数据）、C16（指引引擎）、某个 C 任务（锚点没登记）、某个 G 任务（first 没发或发早了）
