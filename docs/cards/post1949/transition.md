# 从 1949 关结尾到选新行当

阶段名用已经预留的 `branch_pick`（G02）。当铺这关的日结走完、银元重新成为硬通货、铺子按新的利率规定难以为继之后，进入这个阶段。不在这个阶段发随机命运牌。

## 解锁条件

四个条件一起看，不是单一门槛。选不了的行当仍出现在列表里，标成现在不能选，并写明缺哪一条（用原因键，不写对白）。

| 条件 | 看什么 | 打开哪条路 |
|---|---|---|
| 人脉 | 周妈还在人脉里 | 茶馆 |
| 人脉 | 陈文庭还在人脉里，且没有「走了 / 被扣」 | 中药铺 |
| 人脉 | 李敬之还在人脉里 | 教书 / 代写书信 |
| 钱和家当 | 开局本钱 = 身上的钱 + 仍归自己的铺面、住房折成的一笔整数 | 信托商店、杂货铺、修理铺都要一笔开局本钱；不够就只能先选不花钱的路，或选不了 |
| 档案簿 | 认识的人 = 已有碎片的人数。人越多，新行当开局带出的老面孔越多 | 所有行当 |
| 本心和风声 | 本心过低，或风声档过高 | 有的行当选不了；或者选得了，但开局手里多一张 `kp.history_issue` |

数字门槛全部标【待调】。设计只定「看哪几个已有字段」，不定最终切分。

信托商店不绑某一个人脉，绑的是「还有铺面或一笔本钱」。茶馆、中药铺、教书绑人脉。杂货铺、修理铺只看本钱和风声。

## `kp.history_issue`（历史问题）

留着的牌，不是命运牌，不进随机池。

| 字段 | 设计 |
|---|---|
| id | `kp.history_issue`（正式数据以后放 `data/cards/branch/`，这一轮不落地） |
| type | `kept` |
| weight | 0 |
| keepable | true |
| expires_days | 0（不随日子自己消失） |
| 何时进手 | 只在 `branch_pick` 结算时，若风声档或本心越过【待调】的那一档，`add_card` 到 `kept` |
| 何时被翻出来 | 只在按年份日程发出的政策事件的 `conditions` 里查 `has_kept`。查到了，该事件走「查账 / 要说明」那一条，不另掷、不另扣一笔随机的坏处 |
| 不做什么 | 不挂随机命运、不在每天日结里掷、不因为这张牌单独封铺或抓人 |

玩家可以一直留着它。政策事件处理完，那一张事件自己决定这张牌还留不留（`remove_card` 或继续留），仍然是日程上的确定结果。

## 存档

新命名空间 `branch`，与 `core` / `loop` / `ui` 并列。里面只放：选中的行当 id、开局本钱整数、已解锁行当列表、政策事件是否已经发过（按 id）。

不改当铺年代已有键的含义。指引进度仍在 `ui`，不进哈希（合同 §6.1）。`kp.history_issue` 若在留着的牌区里，跟其他留牌一起存，不另造一份。
